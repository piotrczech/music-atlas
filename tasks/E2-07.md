# Representation maps and cluster exploration

Build a reproducible exploratory comparison of the acoustic features and pretrained embeddings.
Fit preprocessing and dimensionality reduction on training data, create PCA and UMAP views for a
fixed representative sample, and colour or filter points by genre and artist. Apply one
clustering method in the appropriately normalised representation space, recording its parameters
and any quantitative summaries separately from the two-dimensional display.

Inspect outliers, mixed clusters and clusters dominated by one artist using a small set of
listening examples. Explain which patterns seem musically meaningful and which may reflect
projection settings, label imbalance or recording conditions. Export coordinates and compact
summaries keyed by track ID for the later dataset-exploration interface.

### Starting from stage 1

- Fit scaling and reductions on the training partition and colour by the top-level genres and
  `artist_id` from the manifest; the artist-limited split keeps prolific artists in training,
  where they can dominate clusters.
- `music_atlas.data_report.concentration` measures artist concentration per group and can be
  reused for clusters.
- The data notebook dropped its PCA map of FMA's published features to stay focused; maps of
  our own representations belong here. `umap-learn` is not yet a dependency.

### Tracking (E2-01)

- Record each run with `music_atlas.tracking.track()` and expose it as `--track`; `atlas
  quick-sample --track` is the reference and the `atlas-tracking` skill the convention. Call
  `run.log_dataset` once per partition read: counts that describe the data go there, metrics
  hold only what the step measured. On WCSS, `sbatch ... --track` logs to PD and
  `scripts/mlflow-ui.sh --wcss` shows the runs locally.
- Name the representation runs it reads (`run.log({"features_run": ..., "embeddings_run":
  ...})`) and log the fixed sample with `log_dataset`. Put maps and cluster summaries under
  `evaluation/`, record clustering parameters and scores as params and metrics, and keep the
  exported coordinates keyed by track ID in the run directory.
