# Log-mel spectrogram processing

Implement log-mel spectrogram generation on top of the shared research loader. Fix and record
the FFT size, hop length, mel-band count, frequency range and conversion to log power, including
the reference level and clipping convention. Define the tensor layout, handling of short windows
and any normalisation required by the CNN. A recording must receive the same transform during
training and application inference.

Inspect representative spectrograms, including silence and difficult recordings, then measure
the compute and storage cost on the quick sample. Choose on-demand calculation or a bounded,
sharded cache based on that measurement. The output should be usable by the CNN task without
saving an unrestricted second copy of the full audio collection as image files.

### Starting from stage 1

- `load_windows` returns mono float32 windows with their time bounds; the quick profile gives
  one centred 10 s window (220,500 samples at 22,050 Hz), the full profile three.
- Every partition track decodes. Tracks under 10 s give one window padded with zeros, so the
  transform needs a fixed convention for that silent tail (the clipping floor, a mask or the
  real length kept alongside).
- PD is Lustre: a cache of one file per spectrogram would hit file-count limits. If caching
  pays off, write one file per tar shard or compute on demand.
- The CNN that consumes this transform is trained in stage 3 (E3-04), and the application must
  apply the same transform to an uploaded recording.
