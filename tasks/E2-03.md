# Feature analysis and initial genre baseline

Use the extracted acoustic features to establish the first classification result on the shared
genre mapping and split. Fit a simple frequency-based reference and a regularised
logistic-regression model appropriate for the agreed multilabel task. Put scaling and any
imputation inside the training pipeline, choose thresholds using validation data, and report
macro-F1, micro-F1, mAP and per-class support with the run configuration.

Inspect feature ranges, missing values and strongly correlated groups to explain obvious
modelling issues before expanding the comparison. Save the fitted preprocessing, class mapping
and model together. This is the common baseline for the next modelling stage; keep the
implementation small and leave the final test partition untouched.

### Starting from stage 1

- Label columns come from `labels.json` (16 top-level genres, all scored); build the label
  matrix from `genre_ids` as in the data notebook, section 4.
- `summary.json` holds the frequency baselines to beat. On validation, a constant score gives
  mAP 0.106 and predicting the most frequent genre gives macro-F1 0.034.
- Classes are strongly imbalanced (Experimental about 36% of tracks, Easy Listening 0.7%) and
  a missing tag is unknown rather than negative; read per-class results with their support.
- `balanced_eval.parquet` is a diagnostic per-genre view; keep it apart from the main metrics.

### Tracking (E2-01)

- Record each run with `music_atlas.tracking.track()` and expose it as `--track`; `atlas
  quick-sample --track` is the reference and the `atlas-tracking` skill the convention. Call
  `run.log_dataset` once per partition read: counts that describe the data go there, metrics
  hold only what the step measured. On WCSS, `sbatch ... --track` logs to PD and
  `scripts/mlflow-ui.sh --wcss` shows the runs locally.
- Log validation metrics as numbers, per genre as nested dicts (`{"recall": {...}}` becomes
  `recall/Rock`), the per-class report under `evaluation/` and the small fitted scaler, class
  mapping and model under `model/`. Name the feature run it reads (`run.log({"features_run":
  run_id})`). Log no test metrics until the final evaluation.
