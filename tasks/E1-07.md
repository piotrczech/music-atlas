# Reproducible quick profile and data smoke run

Connect the shared loader to the quick profile using the dataset format from #5 / PR #13
(`docs/EXPERIMENTS.md`). Read the sample from `$ATLAS_DATA_DIR/ready/<version>/train.parquet`:
use `pre-audit-v1` until E1-03 freezes the audited primary benchmark, then switch to that
version. Each row already carries `shard`, `audio_path`, `artist_id`, `genre_ids`, `valid` and
`duplicate_group`, and `labels.json` marks which genre columns are scored.

Select up to 128 valid training tracks deterministically from the agreed seed, covering the
scored genres and as many distinct artists as possible, without using validation or test data
to choose the sample. If a task needs development metrics, draw a separate fixed sample from
`validation.parquet` of the same version. Save the selected track IDs with the dataset
`version` and `manifest_sha256` from `summary.json`, the seed and the profile, so every team
member reproduces the same input and a regenerated dataset is detected instead of mixed in.
Do not edit the split files: report tracks the loader rejects as `track_id,error`, the same
form representation runs record with `atlas fma-record-filter`.

Run the loading/window-selection path on this sample locally where practical and on WCSS,
recording elapsed time, memory and failed-track counts. The result is a small working input for
parallel representation development and an initial throughput estimate. Local work should
require only the selected audio, not a second copy of FMA-full.

Audio is stored in tar shards on Lustre. Confirm that the E1-06 loader reads a track from
its shard (a tar member opened with `tarfile`) without unpacking it on Lustre, and add a test.
Keep the selected tracks as one small archive so local runs need neither the shards nor
FMA-full.

FMA-full is complete on the music service PD (156 shards, 106,574 tracks, inventory and
metadata). On WCSS, set up your clone and `~/.atlas-env.sh` as in `docs/DEVELOPMENT.md`;
`notebooks/fma_shards.ipynb` shows how to read the shards. Inspect results in an OOD notebook
with the "Music Atlas" kernel and run the processing itself as `sbatch` jobs.
