# Reproducible quick profile and data smoke run

Connect the validated manifest and shared loader to the quick profile. Select up to 128 training
tracks deterministically from the agreed seed, covering available genres and artists without
using validation or test data to choose the sample. Save the selected track IDs and manifest
reference so that every team member can reproduce the same input. Use a separate fixed
validation sample if a task needs development metrics.

Run the loading/window-selection path on this sample locally where practical and on WCSS,
recording elapsed time, memory and failed-track counts. The result is a small working input for
parallel representation development and an initial throughput estimate. Local work should
require only the selected audio, not a second copy of FMA-full.

Audio is stored in tar shards on Lustre. Confirm that the E1-06 loader reads a track from
its shard (a tar member opened with `tarfile`) without unpacking it on Lustre, and add a test.
Keep the selected tracks as one small archive so local runs need neither the shards nor
FMA-full.

FMA-full is complete on the music service PD (156 shards, 106,574 tracks, inventory and
metadata). On WCSS, set up your clone and `~/.atlas-env.sh` as in `docs/DEVELOPMENT.md`;
`notebooks/fma_shards.ipynb` shows how to read the shards. Inspect results in an OOD notebook
with the "Music Atlas" kernel and run the processing itself as `sbatch` jobs.
